## 0. 產品定位

一套**輔助 Delft3D FM Suite（D-Flow FM / D-HYDRO 1D2D）日常工作**的 Windows 桌面工具。
不取代 Delta Shell GUI，而是補上 GUI 做不到、或做起來容易出錯的環節：

| 工作階段 | 使用者在做的事 | 本工具的輔助 |
|---|---|---|
| **① 建置模型** | 在 Delta Shell 建網格、斷面、結構物、邊界、雨量，反覆修改 | 版本控管（時光機、遠端備份、多人同步）、模型檔檢視與比較 |
| **② 執行模擬** | 匯出 DIMR、分割、MPI 平行計算、盯著 log | 情境設定（換雨型）、預檢擋錯、一鍵分割與執行、進度監控、批次佇列 |
| **③ 檢視成果** | 開 map/his 看淹水深度、抽水量、比較情境 | 結果檢核（判定有效／可疑／無效）、最大淹水深度統計與匯出、時序圖、多情境比較 |

使用者：公司內部水理模擬工程師（非軟體背景），單機操作，模型規模約百萬級網格、8 核心 MPI。

## 1. 整體工作流程與資料夾關係

```
 Delta Shell 專案（受版本控管）                 DIMR 匯出資料夾（不受版本控管）
 ┌──────────────────────────────┐   匯出    ┌──────────────────────────────────┐
 │ <專案>.dsproj                 │ ───────▶ │ DIMR\dimr_config.xml               │
 │ <專案>.dsproj_data\           │ (Delta   │ DIMR\dflowfm\*.mdu / *.ext / *.bc … │
 │   └ 各模型輸入檔               │  Shell)  │ DIMR\dflowfm\output\ ← 計算結果     │
 └──────────────────────────────┘          └──────────────────────────────────┘
        ▲ ① 建置：版本控管模組                      ▲ ② 執行模組   ▲ ③ 成果模組
        │   （Git + LFS，只追蹤這兩項）               │  （不碰 Git）  │ （唯讀 output）
```

- **版本控管只管 `.dsproj` / `.dsproj_data`**：`.gitignore` 預設忽略其他所有檔案，因此 DIMR 匯出資料夾、
  `output\`、執行 log、預檢備份（`_backup\`）都**不會**進入 Git。這是刻意的設計：
  模型「原始設定」有版本，計算產物不進版本庫。
- **執行模組以 DIMR 匯出資料夾為單位**（含 `dimr_config.xml`），不要求資料夾有 Git。
- ⚠️ 待確認的設計議題：情境精靈（run SPEC P5）直接修改 DIMR 資料夾內的 MDU / .ext；
  這些修改**不會回寫到 `.dsproj`**，下次從 Delta Shell 重新匯出會被覆蓋。需決定：
  (a) 接受此行為並在 UI 明確提示；或 (b) 另外記錄「情境差異」讓使用者可重新套用。見 §6 待決事項。

## 3. 程式架構

```
app.py                      程式入口（Flet，v2.0）
app_ctk.py                  舊版 CustomTkinter 介面（v1.2.1，穩定後刪除）
ui/                         畫面：theme、dialogs、workspace、home、build_workspace
assets/                     程式圖示（icon.ico、icon.png）
build_exe.bat               雙擊打包（先測試再 flet pack）
core/                       核心邏輯：不得 import 任何 UI 套件，全部可單元測試
├─ git_control.py           ✅ 版本控管（GitModelManager）
├─ findings.py              📐 Finding / Severity（預檢、檢核、健檢共用）
├─ model_files/             ✅ 逐行模型檔解析器（建置、執行、成果共用）
├─ nc_inspect.py            📐 NetCDF 讀取
├─ install.py / settings.py 📐 Delft3D 安裝偵測、使用者設定
├─ partition.py / runner.py / monitor.py   📐 執行
├─ preflight.py / postcheck.py             📐 預檢、結果檢核
├─ build/                   💡 建置輔助（模型總覽、差異比較、結構物表格）
├─ results/                 💡 成果檢視（淹水統計、時序、情境比較）
└─ d3d_runner.py            ⛔ 舊版（d_hydro.exe），P2 完成後刪除
tests/                      pytest；fixtures 為真實模型檔
docs/                       本文件與各模組規格
research/                   技術雛形（不隨程式發佈）
├─ flet_demo.py             2026-08-20 Flet 視覺雛形（單頁版）
├─ flet_home_demo.py        2026-09-29 主頁面＋三大工作區框架雛形（可操作）
└─ flet_home_demo_screens/  上述雛形的截圖
```

**分層原則**：`core/` 回傳結構化結果（dataclass），UI 只負責呈現。
這樣日後更換 UI 框架（見 UI_PLAN.md）時，`core/` 完全不用動。

### 畫面規劃：主頁面＋三大工作區

程式開啟後先顯示**主頁面**，以 3 個大圖示（卡片）選擇要進行的工作；進入工作區後，
上方是該工作區共用的資訊列，下方以分頁操作。任何工作區都可按 🏠 回主頁，或用右上角小圖示直接切換到另一個工作區。
詳細版面見 [UI_PLAN.md](UI_PLAN.md) §1，可操作雛形：`research/flet_home_demo.py`。

| 工作區 | 共用資訊列 | 分頁 | 現況 |
|---|---|---|---|
| **① 模型建置**（藍） | 工作資料夾（Delta Shell 專案）、Git 身分、瀏覽本機／從雲端下載／狀態檢查 | 本機建置（時光機＋建置快照） | ✅（原「📸 模型建置快照」＋時光機列） |
| | | 推送到遠端（綁定＋推送） | ✅（原「☁️ 遠端伺服器備份」） |
| | | 版本歷史 | ✅（原「📜 版本歷史」） |
| | | 模型總覽（B1，日後可加差異比較 B2） | 💡 |
| **② 執行模擬**（橘） | Delft3D 安裝、DIMR 資料夾、核心數 | 情境設定（換雨型精靈） | 📐 P5（取代隱藏中的舊「📝 情境參數設定」） |
| | | 預檢 | 📐 P3 |
| | | 執行與監控 | 📐 P2＋P4（取代隱藏中的舊「▶️ 執行模擬」） |
| | | 批次佇列 | 📐 P5 |
| **③ 檢視成果**（綠） | 成果資料夾、總判定（有效／可疑／無效） | 結果檢核 | 📐 P4 |
| | | 淹水統計 | 💡 V1 |
| | | 時序圖 | 💡 V2 |
| | | 情境比較 | 💡 V3 |

分組原則：
- **① 只處理受 Git 管理的 Delta Shell 專案**；② ③ 只處理 DIMR 匯出資料夾，不碰 Git（見 §1）。
  因此「情境設定」放在 ②：它修改的是 DIMR 檔案，放在 ① 容易被誤以為會存進版本。
- 「從雲端下載（Clone）」放在 ① 的共用資訊列：它的作用是「換一個工作資料夾」，與「瀏覽本機」同性質。
- 尚未實作的分頁先顯示「規劃中」與預計內容，不放可操作的按鈕。
