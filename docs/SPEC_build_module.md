## 0. 目標與範圍

在 Delta Shell 建置模型的過程中，補上 GUI 不方便做的「**看全貌、比差異、查錯**」。

- 以 P1 的 `core/model_files/` 解析器為基礎，**唯讀**為主；需要修改模型檔的功能（情境精靈）放在 run SPEC P5。
- 讀取來源：`.dsproj_data` 內的模型輸入檔，或 DIMR 匯出資料夾（兩者擇一，由使用者選）。
- 核心程式放 `core/build/`，不得 import UI 套件。
- UI 位置：「① 模型建置」工作區（`docs/UI_PLAN.md` §1.3）。B1 為「模型總覽」分頁；B2～B4 若實作，可併入該分頁或另開分頁（待決事項 D12）。
- 換雨型精靈（情境設定）已確定放在「② 執行模擬」工作區，不屬本模組。

## 1. 候選功能

### B1 模型總覽
一頁摘要目前模型：
- MDU 關鍵參數：時段（本地時間）、DtUser、HisInterval、MapInterval、NcFormat、StatsInterval、Tzone。
- 引用檔清單與是否存在（與預檢 E03 共用邏輯）。
- 網格規模：2D 網格數、1D 節點數、邊數（讀 net.nc 維度）。
- 外力：邊界數、雨量來源（NetCDF／.bc）、quantity（`rainfall` vs `rainfall_rate`）。
- 結構物統計：各類型數量（實例：pump 118、orifice 57、bridge 6、weir 2）。
- 可匯出 txt，附在建置快照說明或報告中。

### B2 版本差異比較
選兩個版本（時光機的分支），列出模型設定差異：
- MDU：逐 key 比較（key 不分大小寫），只列有差異的項目。
- structures.ini：新增／刪除／參數改變的結構物。
- .ext：新增／刪除／變更的區塊。
- 大檔（net.nc、地形）只比較大小與雜湊，不比內容。
- 與版本控管模組的交界：以 `git show <分支>:<路徑>` 取出舊版檔案內容（**唯讀**，不切換工作資料夾）。
  → 需在 `GitModelManager` 新增唯讀方法，屬版本控管模組的變更，需明確核准。

### B3 結構物表格
- structures.ini 以表格呈現（id、名稱、類型、所在分支／位置、主要參數如 pump capacity、堰頂高）。
- 篩選、排序、匯出 CSV。
- 參數為時間序列檔名時標示出來（與 DOMAIN_NOTES §10 一致）。

### B4 建置期模型健檢
重用預檢規則引擎（`preflight.py` 的 `Finding` 架構），只挑「與執行設定無關」的規則在建置時先檢查：
- 引用檔缺漏（E03）、雨量 quantity 與單位（W02）、雨量空間範圍（W07）。
- 1D2D 常見問題（需再確認可自動判斷的項目）：糙度檔缺值數量、人孔底高低於儲存區底高
  （DOMAIN_NOTES §9 的初始化警告，目前要跑模式才看得到；評估能否在建置期直接從輸入檔算出）。

## 2. 優先順序建議

| 順序 | 功能 | 理由 |
|---|---|---|
| 1 | B1 模型總覽 | 幾乎全部由 P1／P3 的解析器組成，成本最低 |
| 2 | B2 版本差異比較 | 與已完成的版本控管最能互補，回答「這版跟上一版改了什麼」 |
| 3 | B4 建置期健檢 | 等 P3 預檢規則穩定後再抽出共用 |
| 4 | B3 結構物表格 | 需求強度待確認 |
