## 2. 背景與動機

`app.py` 是 Python + CustomTkinter 的桌面 GUI，功能完整但視覺偏樸素。評估「換成更美觀的介面」是否可行、划不划算。

## 3. 考慮過的選項與取捨

| 方案 | 說明 | 優點 | 缺點 |
|---|---|---|---|
| **維持 Python + 換 UI 框架（Flet）** | 只重寫 UI 層，`core/` 完全不動 | 核心邏輯（裸儲存庫、LFS 等）完全保留；現代化卡片式／圓角／動效介面；仍可打包成單一 .exe | UI 層要重寫一次；元件寫法不同，需要重新學 |
| 維持 Python + 換 UI 框架（PyQt6/PySide6） | 同上，換成 Qt | 成熟穩定、元件豐富、客製化空間大 | 重新設計外觀的工作量比 Flet 多；授權（PySide6 LGPL／PyQt6 GPL 或商用）需留意 |
| Web／桌面混合（Electron、Tauri） | 前端 HTML/CSS/JS，後端另接 | 畫面自由度最高 | 需拆成前後端兩層，Git／檔案邏輯要重寫成 JS 或以 sidecar 跑 Python；對單機內部小工具不划算 |
| C#/.NET（WPF/WinUI） | 全部重寫成 C# | 原生 Windows 質感最好、效能佳 | 所有業務邏輯（Git、LFS、模型檔解析）要重寫，風險與工作量最大 |

## 4. 推薦方案：Flet

- Flet 是 Python 套件，底層用 Flutter 繪製畫面，可做出卡片、圓角、動效、Material 圖示與色彩語意。
- 仍是 Python，可直接 `import core.*`，**不用重寫任何業務邏輯**。
- 可打包成 Windows 單一執行檔（底層為 PyInstaller），使用方式不變（雙擊 .exe）。
  M0 實測：Flet＋netCDF4 打包後可正常讀檔；約 95 MB、啟動約 5～7 秒。不採用 `flet build windows`（需另裝 Flutter SDK 與 Visual Studio）。
  2026-09-30 改為 `build_exe.py`：畫面引擎（42 MB）不包進 exe，第一次啟動時由 `ui/client_setup.py` 準備，exe 約 19 MB、啟動約 3 秒（詳見 CLAUDE.md「相依套件」）。
- 內建圖表元件，可評估是否取代 matplotlib（成果模組，OVERVIEW D4）。

## 6. 踩坑紀錄（動手前務必先看）

Flet 0.86.5 的 API 與舊版文件／一般認知落差很大：

| 舊寫法（會報錯） | 0.86.5 可用寫法 |
|---|---|
| `ft.padding.symmetric(...)` | `ft.Padding.symmetric(...)`（大寫類別） |
| `ft.border.all(...)` | `ft.Border.all(...)` |
| `ft.ElevatedButton(text="...")` | `ft.Button(content="...")`（元件改名，`text=` 移除） |
| `ft.OutlinedButton(text="...")` | `ft.OutlinedButton(content="...")` |
| 8 碼色碼當成 `#RRGGBBAA`（例：`"#3ba7ff33"` 想要半透明藍） | Flet 是 **`#AARRGGBB`**（alpha 在前），上例會變成橄欖綠；改用 `ft.Colors.with_opacity(0.18, "#3ba7ff")` |
| 中文文字加 `italic=True` | 微軟正黑體沒有斜體字形，中文會變成亂碼般的變形字；中文一律不用斜體，改用小標籤（外框＋小字）區分 |
| `ft.app(target=main)` | 0.86.5 建議 `ft.run(main)` |
| `FilePicker` 加到 `page.overlay` | 0.86.5 為 Service，**在頁面執行期間建立即自動註冊**；`get_directory_path()` 是非同步，處理函式寫成 `async def` |
| 背景執行緒直接 `threading.Thread` 後更新畫面 | 用 `page.run_thread(func)`，才會帶入頁面 context |
| **在 `page.run_thread()` 的背景執行緒呼叫 `page.update()`** | **更新不會送出**，要等使用者下次操作才出現（進度條完全不動）。`ui/runtime.py` 的 `install_thread_safe_update(page)` 在程式啟動時替換 `page.update`：不在事件迴圈上就改用 `page.run_task()` 排進事件迴圈（2026-09-29 實測修正） |
| `control.page` 取得頁面 | 控制項尚未實際加到畫面時會丟 `RuntimeError: Control must be added to the page first`；需要頁面的物件請直接保存 `page` 參考 |
| 對話框用 `page.open(dlg)` | 0.86.5 為 `page.show_dialog(dlg)` / `page.pop_dialog()` |
| `AlertDialog` 內容放可捲動的 `Column(scroll=...)` | 對話框會被撐到整個視窗高；改用 `AlertDialog(scrollable=True)`，內容直接放 `Text` |
| 程式被強制結束（`os._exit`）| 留下 `flet.exe` 視窗卡在「Working...」；測試腳本要用 `taskkill /T` 連子程序一起結束 |
| `ft.Tabs(tabs=[ft.Tab(text="...", content=...)])` | **整個重新設計**：`Tab` 不再帶 `content`，改用 TabBar／TabBarView 分離架構。`flet_demo.py` 以「自製分頁按鈕列＋單一內容區」繞過；`flet_home_demo.py` 延續此做法並實作了切換（點擊後重建內容區） |

**結論**：不能照舊文件或既有印象寫。每個元件都先用 `inspect.signature(元件.__init__)` 對照當時安裝的版本，
並先查一次 Flet 官方最新文件確認 `Tabs` 用法。`requirements.txt` 需鎖定 Flet 版本。
